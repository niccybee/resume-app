# Use extensible JSON Resume-compatible Block schemas

The MCP contract uses validated, kind-specific CV Block schemas whose canonical fields align with JSON Resume: skills use `name`, `level`, and `keywords`; certifications use `name`, `date`, `url`, and `issuer`; education uses `institution`, `url`, `area`, `studyType`, dates, `score`, and `courses`; and interests use `name` and `keywords`. Experience remains deliberately granular: each Experience Block contains one `text` achievement, while its Employment Occasion maps to a JSON Resume `work` entry and its selected Block Versions become `highlights`. Dates accept JSON Resume's year, year-month, or full-date forms; ongoing employment omits `endDate` rather than storing `present`.

Block schemas and Composition adapters are versioned and format-neutral so coverage can expand across additional JSON Resume sections, future JSON Resume schema versions, and other document formats without rewriting existing Block Versions or CV Revisions. New fields and kinds enter through named validated schemas or adapters rather than arbitrary unvalidated properties. This preserves reliable MCP tool calls while keeping the authoring model broader than any one export format.
